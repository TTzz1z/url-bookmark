# 一、最终实施方案选择

## 1. 确定采用的技术方案

- Next.js + TypeScript
- SQLite 本地数据库
- Drizzle ORM
- 原生 Fetch / Undici 抓取网页
- JSDOM 解析 HTML
- Mozilla Readability 提取正文
- DOMPurify 清理正文 HTML
- Turndown 转换 Markdown
- React Markdown 渲染正文
- Vitest 执行单元和集成测试
- Playwright 只用于最终核心流程 E2E 测试
- 本地开发与生产运行方式
- Windows `setup.bat` 与 `start.bat`

## 2. 最终范围调整

为降低笔试项目延期风险，对原设计作以下调整。

### 2.1 P0 必须完成

- 粘贴网址收藏
- 自动获取标题
- 正文提取
- Markdown 转换和保存
- 标签添加和筛选
- 标题、网址、正文、备注关键词搜索
- 书签增删改查
- 抓取状态和错误提示
- 重新提取
- SQLite 持久化
- 本地完整运行
- 核心流程自动化测试
- README、设计说明、AI 使用说明和演示材料

### 2.2 搜索方案调整

P0 阶段优先使用：

```text
SQL LIKE 查询 + 标签关系查询
```

搜索范围：

- 标题
- URL
- 域名
- Markdown 正文
- 用户备注
- 标签

原因：

- 能直接支持中文和英文关键词；
- 实现和调试成本较低；
- 对笔试项目数千条以内的数据完全够用；
- 不让 FTS5 分词和环境兼容性阻塞核心交付。

SQLite FTS5 调整为 P1 优化项。只有在核心功能全部验收通过后再增加。

### 2.3 抓取方式调整

P0 只使用普通 HTTP 请求，不默认引入 Playwright 浏览器抓取。

原因：

- 运行包更小；
- 启动更简单；
- 抓取速度更快；
- 更适合本地运行交付；
- 登录页、验证码和强动态网页可以明确标记失败。

### 2.4 调整为 P1 的功能

以下功能不阻塞最终交付：

- 单篇 Markdown 文件下载
- 标签独立管理页面
- FTS5 全文索引
- 提取状态筛选
- 收藏统计
- 深色模式

### 2.5 暂不开发

- 批量 ZIP 导出
- 浏览器扩展
- AI 自动标签
- AI 摘要
- PDF、截图和完整网页归档
- 多用户和登录
- 浏览器渲染抓取
- 云端同步
- 移动端应用

