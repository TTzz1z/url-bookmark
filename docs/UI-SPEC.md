# 网址收藏夹 UI 规范

## 1. 视觉方向

唯一视觉基准为 `docs/UI-REFERENCE.png`（1196 × 1315）。整体采用轻量、克制、
高信息密度的蓝白阅读工具风格：固定左侧导航、顶部工具栏、白色内容卡片与
蓝色主操作形成清晰层级。界面避免后台报表感，不使用大面积渐变、玻璃拟态、
霓虹发光或装饰性插画。

视觉关键词：清爽、专注、可信、轻量、阅读优先。

## 3. 字体层级

字体栈：`Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`。

| 层级 | 字号 / 行高 | 字重 | 用途 |
|---|---|---|---|
| Display | 24px / 32px | 700 | 页面主标题 |
| Title | 18px / 26px | 700 | 书签标题、详情文章标题 |
| Heading | 16px / 24px | 650 | 分区标题、正文二级标题 |
| Body | 14px / 22px | 400 | 正文、说明 |
| Label | 13px / 18px | 500 | 按钮、标签、导航 |
| Meta | 12px / 18px | 400 | 时间、域名、状态说明 |

正文阅读区最大宽度 72ch，中文正文行高不低于 1.75。

## 4. 间距体系

基础单位为 4px，常用间距：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40`。

- 页面外边距：桌面 20px，移动端 16px；
- 卡片内边距：桌面 18–20px，移动端 16px；
- 表单控件间距：12px；
- 标题与元数据：8px；
- 列表卡片间距：12px；
- 大分区间距：24–32px。

## 5. 圆角、阴影与边框

- 主卡片圆角：12px；
- 输入框、下拉框、按钮圆角：8px；
- 标签和状态胶囊圆角：999px；
- 卡片边框：`1px solid var(--color-border)`；
- 默认阴影：`0 4px 18px rgba(22, 34, 58, 0.05)`；
- 悬停阴影：`0 8px 24px rgba(22, 34, 58, 0.08)`；
- 不使用高饱和外发光。

## 6. 组件规范

### 按钮

- 主按钮：品牌蓝底、白字、40px 高，悬停颜色加深并轻微上移 1px；
- 次按钮：白底、灰边框、深色文字；
- 危险按钮：白底红字红边框，确认后才执行删除；
- 图标与文字间距 8px，图标使用统一线性图标库，不使用 Emoji；
- 所有可点击控件最小触控尺寸 44 × 44px。

### 输入框

- 40–44px 高，白底、1px 灰边框、8px 圆角；
- 聚焦显示 `#2460EB` 边框和 3px 半透明焦点环；
- 错误态使用失败色边框并在控件下方展示可理解的中文说明。

### 标签

- 默认标签：浅灰蓝背景、灰蓝文字；
- 被选中的筛选标签：浅蓝背景、品牌蓝文字与蓝色边框；
- 书签标签前置 6px 圆点或统一小标签图标；
- 支持鼠标点击筛选和键盘聚焦。

### 状态

- `success`：绿色圆点/图标 + “提取成功”；
- `partial`：琥珀色圆点/图标 + “部分提取”；
- `failed`：红色圆点/图标 + “提取失败”；
- `pending`：灰蓝色旋转/等待图标 + “正在提取”；
- 失败详情使用浅红背景的内嵌提示条，展示错误码与可读原因。

## 7. 桌面布局

### 1440px / 1280px

- 左侧导航固定宽度 216px；
- 主区域宽度自适应，内容最大宽度 1160px；
- 顶部工具栏高度约 56px；
- 首页收集输入和按钮同排；
- 列表为单列内容卡片，缩略图 112 × 84px；
- 详情页使用主内容与信息侧栏双栏，比例约 2:1；
- 侧栏信息卡在视口允许时保持粘性。

## 8. 移动布局（最小 390px）

- 左侧导航折叠为顶部品牌栏与可展开筛选抽屉；
- 收集输入与按钮改为上下排列，按钮占满宽度；
- 搜索、排序和筛选允许换行或横向滚动；
- 卡片缩略图缩为 72 × 72px，失败提示独占下一行；
- 详情页改为单列：操作区、正文、书签信息依次排列；
- 固定操作不得遮挡正文，所有核心操作可通过键盘与触控完成。

## 9. 首页信息层级

1. 品牌与页面标题；
2. 新建收藏输入与主要动作；
3. 搜索、排序与状态/标签筛选；
4. 书签卡片：标题 → 域名/URL → 摘要 → 标签；
5. 状态与时间；
6. 空列表、搜索无结果、加载与失败状态。

## 10. 详情页信息层级

1. 返回列表与主要操作（重新提取、编辑、删除）；
2. 书签标题、来源 URL、状态与时间；
3. 阅读模式 / Markdown 源码 / 编辑模式切换；
4. Markdown 阅读正文；
5. 侧栏中的标签、备注、来源信息与错误详情；
6. 用户编辑过正文时，重新提取前必须明确确认覆盖。

## 11. 交互与无障碍

- 所有异步状态通过 `aria-live` 通知；
- 键盘焦点清晰可见；
- 图标按钮必须有中文 `aria-label`；
- 页面只使用一个 `h1`，正文标题层级连续；
- 动画只用于 160–220ms 的悬停、加载和内容切换，并遵守
  `prefers-reduced-motion`；
- 加载、空列表、搜索无结果和正文提取失败均使用同一套卡片语言补全，
  不创造另一套视觉风格。
