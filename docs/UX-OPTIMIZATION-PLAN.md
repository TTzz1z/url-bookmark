# 网址收藏夹：前端体验审计与全面优化方案

审计日期：2026-07-31

## 1. 结论

当前版本已经具备完整且可信的功能骨架：列表、搜索、标签、提取状态、阅读、
Markdown 源码、编辑、重新提取、导出、删除撤销、暗色模式、快捷键、空状态和
移动端适配都不是占位实现。真正需要优化的不是“再加一套视觉风格”，而是重新
建立任务主次。

推荐的产品方向是：

> 从“功能都摆在界面上的收藏管理页”，升级为“状态可解释、阅读更沉浸、整理更
> 安全的本地资料库”。

保留现有品牌蓝、白色内容面、Phosphor 图标、12px 圆角、轻阴影和衬线阅读正文；
重点调整信息层级、状态权重、编辑安全感和宽屏排版。

### 总体健康度

| 流程              | 健康度     | 核心判断                                                       |
| ----------------- | ---------- | -------------------------------------------------------------- |
| 1. 浏览与查找收藏 | 需优先调整 | 功能完整，但工具栏挤压标题、状态视觉过量、导航层级重复         |
| 2. 阅读正文       | 基础良好   | 正文排版成熟，但“专注模式”名不副实，关键信息默认被隐藏         |
| 3. 编辑与整理     | 需优先调整 | 能完成任务，但缺少保存确认、草稿保护、标签选择和 Markdown 预览 |

- `src/components` 下全部前端组件；

本轮视觉证据为用户提供的三张当前桌面截图：

1. 收藏列表；
2. 阅读模式；

## 3. 最高优先级问题

### P0-1 首页工具栏重排

现状：`page-toolbar` 把页面标题、搜索、五个状态筛选和排序放进一个可换行 flex
容器。即使在超宽屏上，“全部收藏”仍被压成两行，排序掉到下一行右侧，首屏出现
明显的横向碎片感。

证据：

- `src/components/home-screen.tsx:924`
- `src/app/globals.css:617`
- 当前列表截图

建议：

- 第一行只放页面标题、结果数和一个主动作；
- 第二行使用统一的工具栏容器：搜索框占满剩余空间，右侧为筛选与排序；
- 状态筛选独立成第三行或工具栏下沿，不再与标题争宽度；
- 宽屏内容轨道统一为 1080–1160px，标题、工具栏、添加入口和卡片左边缘对齐；
- 1040px 以下自动分成两行，而不是靠偶然换行。

验收标准：

- 1280px 及以上“全部收藏”不得被工具栏挤成两行；
- 搜索、筛选和排序不能形成孤立的第二行按钮；
- 390px 下无横向页面溢出，筛选横滑时有渐隐提示。

### P0-2 成功状态降噪，异常状态增权

现状：成功卡片同时使用绿色边框、浅绿渐变、左色条和绿色状态徽标；成功是列表
里的正常状态，却获得了与失败相同甚至更强的视觉强调。大量成功条目让界面持续
发绿，削弱了部分提取和失败的辨识度。

证据：

- `src/app/globals.css:1230`
- `src/app/globals.css:1246`
- 当前列表截图

建议：

- 成功卡片恢复为中性白色，只保留低饱和成功徽标，或在常规列表中隐藏徽标；
- 左侧状态色条只用于 `pending / partial / failed`；
- `partial` 使用琥珀提示条和“重新提取 / 手动编辑”动作；
- `failed` 使用红色内嵌错误说明、可理解原因和明确的下一步；
- 状态筛选增加数量，如“失败 2”“处理中 1”，优先帮助用户处理异常。

### P0-3 统一操作语义

现状：

- 卡片菜单中的“重新提取”实际上只导航到详情页，并没有触发重新提取；
- 详情页“编辑信息”和“编辑模式”是两个重复入口；
- 详情页删除立即执行，没有确认；设计规范却要求删除确认；
- 列表整卡、标题和“阅读全文”同时承担进入详情的职责。

证据：

- `src/components/home-screen.tsx:240`
- `src/components/detail-screen.tsx:524`
- `src/components/detail-screen.tsx:552`

建议：

- 如果菜单项只打开详情，改名为“查看并重新提取”；更优方案是在卡片内直接执行；
- 详情顶部保留一个“编辑”主入口，标签页继续表示当前模式，不再重复同一 CTA；
- 详情删除必须确认；列表删除可保留“立即删除 + 8 秒撤销”的轻量模式；
- 标题或整卡作为唯一主热区，“阅读全文”改为悬停/聚焦时出现的辅助提示。

### P0-4 编辑保存必须有明确闭环

现状：保存成功后直接切回阅读模式，没有成功通知；保存按钮在长正文底部；只有
切换标签时会提示未保存，刷新、关闭页面和浏览器返回仍可能丢失内容。

证据：

- `src/components/detail-screen.tsx:301`
- `src/components/detail-screen.tsx:699`

建议：

- 编辑页顶部或底部增加粘性保存栏；
- 明确显示“未保存 / 正在保存 / 已保存 14:32 / 保存失败”；
- 支持 `Ctrl/Cmd + S`；
- 增加 `beforeunload` 防丢失确认；
- 按书签 ID 保存本地草稿，并在重新进入时提供“恢复草稿”；
- 保存成功后显示 toast，不强制立即退出编辑；让用户决定继续编辑或返回阅读。

### P0-5 修复正文与状态文字对比度

浅色主题中多处小字号文字对比度不足：

| 用途         | 前景 / 背景         | 实测对比度 |
| ------------ | ------------------- | ---------: |
| 三级元数据   | `#98A2B3 / #FFFFFF` |     2.58:1 |
| 成功徽标     | `#24B47E / #E8F8F1` |     2.42:1 |
| 部分提取徽标 | `#C17A00 / #FFF6DE` |     3.22:1 |
| 失败徽标     | `#E84C5B / #FFF0F1` |     3.38:1 |

这些颜色大量用于 10–12px 文本。建议：

- 真实元数据文字改用 `--color-text-secondary` 或新的高对比 Meta token；
- 成功文本直接使用已经存在的 `--color-success-text`；
- 失败文本使用 `--color-failed-text`；
- 为部分提取新增更深的文本色；
- 颜色仍可保持柔和，但小字号文本目标至少 4.5:1。

## 4. 推荐布局

### 4.1 全局框架

- 顶栏只承担品牌、全局返回、主题/数据入口；
- 删除当前无行为的“本地用户 + 下拉箭头”，避免制造假入口；
- 如果需要保留右上角入口，改为“本地数据”菜单，承载存储、备份和主题；
- 侧栏固定宽度可维持 216–224px；
- “全部收藏”是主导航，“全部标签”只是标签筛选的清空项，二者不应同时呈现选中态。

### 4.2 侧栏

- 主导航：全部收藏、标签管理；
- 标签分组：全部、常用标签、更多；
- 默认隐藏数量为 0 的标签，或把它们放进“更多”；
- 存储卡不再用无配额进度条暗示“空间快满”；
- 如果显示横条，必须标明它表示“数据库 / 图片构成”，不是容量使用率；
- 移动抽屉打开后移动焦点、锁定背景、支持 Escape 关闭并把焦点还给触发按钮。

### 4.3 收藏列表

推荐卡片层级：

1. 标题；
2. 域名、收藏时间、状态；
3. 两行摘要；
4. 标签与一行备注；
5. 仅在悬停、聚焦或触屏时显示外链和更多操作。

具体调整：

- 标题允许最多两行，不在桌面强制单行截断；
- 域名徽标可使用已有 favicon，加载失败回退到 Globe 图标；
- URL 默认只显示域名，完整 URL 放在 tooltip 或详情；
- 成功卡片保持中性；
- 部分/失败卡片把错误说明和动作放在摘要区，而不是只靠颜色；
- 备注改为常规文字，不使用斜体作为主要区别；
- 列表更新时保留旧内容并显示细进度，不要每次搜索都让整列退回四张骨架卡。

### 4.4 阅读页

建议默认展示右侧信息栏，用户主动进入专注阅读时才隐藏。

当前“专注模式”只隐藏信息栏，侧栏、顶部、标题和操作仍在，因此建议二选一：

1. 改名为“隐藏信息栏”；或
2. 实现真正专注模式：隐藏侧栏与详情头，只保留窄正文、阅读进度和浮动退出按钮。

正文建议：

- 阅读宽度保持 64–70ch，现有 68ch 合理；
- 增加字号 16/18/20、版心窄/宽、衬线/无衬线三个本地偏好；
- 阅读进度按正文容器的开始和结束位置计算，不按整页滚动高度；
- 顶部操作精简为“编辑”和“更多”，重新提取、导出、删除进入更多菜单；
- 导出不应只有进入 Markdown 源码后才发现；
- 重新提取时保留旧正文可读，只在顶部显示非阻塞进度，不用模糊遮罩覆盖全文。

### 4.5 编辑页

桌面推荐双栏：

- 左侧 55–60%：Markdown 编辑器；
- 右侧 40–45%：实时预览；
- 标题、标签、备注作为正文编辑器上方的可折叠“书签信息”区；
- 900px 以下切换为“编辑 / 预览”标签。

标签输入改为组合框：

- 输入时匹配 `allTags`；
- 已选标签显示为可删除 chip；
- 回车创建新标签；
- 明确显示 12 个上限；
- 避免让用户理解“逗号分隔”和大小写去重规则。

编辑器还应补充：

- 标题和备注字数计数，仅接近上限时显示；
- 行号可选，不作为默认；
- Markdown 常用快捷键或轻量工具栏；
- `Tab` 在编辑器中的行为明确；
- 保存失败后保留全部输入，并把错误放在保存栏，不只依赖短暂 toast。

## 5. 状态与反馈系统

### 5.1 收藏与提取

| 状态          | 列表反馈                           | 可用动作           |
| ------------- | ---------------------------------- | ------------------ |
| 验证网址      | 乐观卡片，显示域名和“正在验证”     | 取消               |
| 获取网页      | 保留卡片位置，阶段文案更新         | 继续浏览           |
| 转换 Markdown | 骨架摘要，不显示虚假百分比         | 继续浏览           |
| 提取成功      | 中性卡片淡入真实标题和摘要         | 阅读、编辑         |
| 部分提取      | 琥珀提示和原因                     | 重新提取、手动编辑 |
| 提取失败      | 红色错误说明，区分可重试与不可重试 | 重试、手动编辑     |

如果后端暂时无法提供真实阶段，不要伪造阶段动画，只显示“正在提取，长文可能需要
十几秒”，并在完成后通过 `aria-live` 和可见状态共同通知。

### 5.2 搜索和筛选

- 输入后 260ms 防抖可以保留；
- 请求过程中保留当前结果，工具栏显示细进度；
- 返回后更新“找到 N 条收藏”；
- 搜索词、标签、状态继续同步 URL；
- 活动筛选 chip 保留，但放到工具栏下方，不夹在添加入口和列表之间；
- 无结果页给出“清除状态 / 清除标签 / 清除全部”三个更针对性的动作。

### 5.3 保存、重新提取和删除

- 成功：toast 或保存栏，4 秒后自动收起；
- 可恢复删除：toast 保留 8 秒并提供撤销；
- 不可恢复操作：确认框必须说明影响范围；
- 重新提取覆盖手工正文：保留现有确认逻辑，并把“标签和备注不会丢失”继续写清楚；
- 错误：页面内保留错误状态，toast 只作为即时通知，不能成为唯一证据。

## 6. 动效规范

现有 `140 / 220 / 380ms` 和 `prefers-reduced-motion` 基础可以保留。

建议动效清单：

| 场景             | 动效                   |      时长 |
| ---------------- | ---------------------- | --------: |
| 按钮 hover/press | 颜色、边框、1px 位移   | 120–160ms |
| 菜单/筛选浮层    | 淡入 + 4px 位移        |     140ms |
| 弹窗             | 遮罩淡入、内容 0.98→1  | 180–220ms |
| 新收藏进入列表   | 透明度 + 6px 位移      |     220ms |
| 提取状态变化     | 徽标文字与颜色交叉淡化 |     180ms |
| 保存成功         | 状态图标轻量切换       |     180ms |
| 侧栏抽屉         | translateX             | 220–260ms |

需要删除或收敛的动效：

- 筛选或搜索后不要让所有卡片再次执行入场动画；
- `pending` 卡片不需要边框和色条同时无限呼吸；
- hover 阴影保持克制，避免每张卡都浮起成独立“仪表盘组件”；
- reduced-motion 下不保留平滑滚动和循环旋转以外的非必要过渡。

## 7. 交互与无障碍

### 必修项

- 状态筛选按钮增加 `aria-pressed`；
- `role="menu"` 的卡片菜单实现方向键、Home/End 和自动聚焦，或者改回普通 disclosure；
- 确认删除时默认焦点放在“取消”，不是右上角关闭；
- 32px 紧凑图标按钮在触控环境提升到至少 44px；
- 移动抽屉实现焦点圈定、Escape、焦点归还；
- 异步结果数量和提取状态改变使用独立的 `aria-live` 文本；
- 搜索和筛选时不要卸载当前焦点所在卡片；
- 添加网址输入框不要在空值 blur 时立即卸载整个表单，否则键盘 Tab 会丢焦点；
- 对话框、抽屉打开时锁定背景滚动；
- 状态必须继续同时使用文字和图标，不能只靠颜色。

### 建议验证

- 390、768、1024、1280、1440 和 2560px；
- 浏览器 200% 缩放；
- 键盘完整完成“添加 → 搜索 → 阅读 → 编辑 → 保存 → 删除/撤销”；
- Windows 高对比度模式；
- 浅色、深色、系统主题；
- `prefers-reduced-motion`；
- NVDA 或 VoiceOver 的标题、标签页、菜单和状态播报。

## 8. 视觉系统调整

### 保留

- 品牌蓝 `#2460EB`；
- 中性灰蓝文字体系；
- 12px 卡片圆角、8px 控件圆角；
- Phosphor 图标；
- 阅读区衬线字体；
- 白色内容面与浅灰页面背景；
- 克制阴影。

### 调整

- 浅色主题三级文字整体加深；
- 成功色只用于状态，不铺满所有正常卡片；
- 标签颜色减少随机彩虹感，颜色只用于识别，不用于表达含义；
- 顶栏和侧栏减少无行为装饰；
- 控件高度统一为 40px 桌面 / 44px 触控；
- 页面主标题 24px，卡片标题 16px，正文 17–18px，Meta 不小于 12px；
- 阴影只用于浮层和 hover，普通卡片主要依靠边框与间距分组。

## 9. 响应式策略

### ≥ 1440px

- 216–224px 侧栏；
- 1080–1160px 主内容；
- 标题独立一行，工具栏完整单行；
- 阅读页默认正文 + 300px 信息栏。

### 900–1439px

- 工具栏分两行；
- 详情头操作可进入更多菜单；
- 阅读信息栏可折叠；
- 编辑器仍可双栏，但预览比例降低。

### 600–899px

- 侧栏抽屉；
- 详情头改为纵向，不要等到 580px 才堆叠；
- 阅读页单列；
- 编辑/预览使用标签切换。

### ≤ 599px

- 搜索独占一行；
- 状态筛选横滑或收进筛选面板；
- 添加表单只保留一个全宽主按钮，取消使用轻量文字或关闭图标；
- 卡片动作始终可见；
- 删除放在更多菜单底部，减少误触；
- 底部保存栏使用安全区 inset。

## 10. 前端结构建议

当前 `HomeScreen`、`DetailScreen` 和 `globals.css` 体积较大，继续增加状态会放大样式
漂移和回归风险。建议在不更换技术栈的前提下拆分。

### 首页

- `CollectionHeader`
- `CollectionToolbar`
- `AddBookmarkForm`
- `BookmarkList`
- `BookmarkCard`
- `BookmarkCardMenu`
- `useCollectionQuery`
- `useBookmarkActions`

### 详情

- `BookmarkDetailHeader`
- `ReaderToolbar`
- `MarkdownReader`
- `BookmarkInspector`
- `BookmarkEditor`
- `BookmarkDraftStatus`
- `useBookmarkDraft`
- `useReExtraction`

### 样式

- `tokens.css`
- `base.css`
- `components/*.module.css`
- `pages/home.module.css`
- `pages/detail.module.css`

如果不希望引入 CSS Modules，至少用 cascade layers 分成
`tokens / reset / components / pages / utilities / responsive`。

## 11. 推荐实施顺序

### 阶段 A：立即修复，1–2 天

1. 首页工具栏重排；
2. 修复标题挤压；
3. 成功卡片降噪；
4. 删除确认与操作文案一致；
5. 保存成功反馈；
6. 浅色主题对比度；
7. 状态筛选 `aria-pressed`；
8. 空 URL blur 丢焦点问题。

### 阶段 B：核心体验，2–4 天

1. 侧栏信息架构；
2. 列表卡片层级；
3. 状态数量与非阻塞刷新；
4. 阅读页默认信息栏与真正专注模式；
5. 阅读工具栏和正确进度计算；
6. 移动抽屉焦点管理。

### 阶段 C：编辑器，3–5 天

1. 粘性保存状态；
2. 草稿恢复与离开保护；
3. 标签组合框；
4. Markdown 编辑/预览双栏；
5. 快捷保存与错误恢复。

### 阶段 D：系统化与回归，2–3 天

1. 组件和样式拆分；
2. 动效收敛；
3. 390–2560px 响应式回归；
4. 键盘、屏幕阅读器、对比度与 reduced-motion 验证；
5. 为 loading / empty / failed / partial / dirty / saved 建立稳定截图。

## 12. 最终验收指标

- 1280px 以上首页标题不因工具栏换行；
- 浅色主题小字号正文和状态文字达到 4.5:1；
- 成功卡片不再使用整卡绿色强调；
- 所有可见入口的文案与实际动作一致；
- 详情删除有确认，列表删除可在 8 秒内撤销；
- 编辑始终可见当前保存状态，刷新前有未保存保护；
- 390px 下所有核心动作可触达且页面无横向溢出；
- 移动抽屉和卡片菜单可完整键盘操作；
- 提取、保存和删除状态既可见又可被辅助技术播报；
- reduced-motion 下无循环装饰动画；
- 搜索和筛选时保持内容与焦点稳定。
